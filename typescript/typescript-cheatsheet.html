TypeScript Cheatsheet

React Native stajı öncesi hazırlık için derlenmiş, sık kullanılan ve unutulunca canını sıkan TypeScript konuları. Sıralama önem sırasına göre değil, konu bütünlüğüne göre.

01 — TEMELLERfoundations
TYPE / 01

Temel tipler

JS'teki primitive'lerin üzerine tip etiketi koyman.

let age: number = 25;
let name: string = "Yigit";
let isIntern: boolean = true;
let data: unknown; // any'nin güvenli hali
let nothing: null | undefined;
dikkat — any kullanmak tip kontrolünü tamamen kapatır. Elinden geldiğince unknown tercih et, gerekirse daralt (narrowing).
TYPE / 02

Array ve Tuple

Tuple, uzunluğu ve sırası sabit array demek.

let scores: number[] = [90, 85, 70];
let names: Array<string> = ["a", "b"];

// Tuple: sabit uzunluk, sabit sıra
let point: [number, number] = [10, 20];
let entry: [string, boolean] = ["done", true];
TYPE / 03

Interface vs Type

İkisi de şekil tanımlar, farkları genişletilebilirlik ve kapsamda.

interface User {
  name: string;
  age: number;
}
// aynı isimle tekrar tanımlarsan birleşir (declaration merging)
interface User {
  email: string;
}

type UserType = {
  name: string;
  age: number;
};
// type union/intersection da yapabilir, interface yapamaz
type ID = string | number;
kural — obje/component prop şekli tanımlarken interface, union/intersection gerekince type kullan. Kesin bir kural yok, tutarlılık önemli.
TYPE / 04

Literal tipler ve Enum

Belirli değerlerle sınırlanmış tipler.

type Status = 'loading' | 'success' | 'error';

function handle(status: Status) {
  if (status === 'error') { /* ... */ }
}

// enum alternatifi, genelde literal union tercih edilir
enum Direction {
  Up, Down, Left, Right
}
dikkat — enum derlenmiş JS'te ekstra kod üretir ve tree-shaking dostu değildir. RN projelerinde çoğunlukla literal union tercih edilir.
02 — FONKSİYONLARfunctions, in depth
TYPE / 05

Fonksiyon tipleri

Parametre, opsiyonel parametre, default değer, rest.

function add(a: number, b: number): number {
  return a + b;
}

// opsiyonel parametre: ? ile
function greet(name: string, title?: string) {}

// default değer
function multiply(a: number, b: number = 2) {}

// rest parametre
function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}
TYPE / 06

Arrow function tipleri

Ok fonksiyonlarında tip yazımı normal fonksiyonla aynı mantık, sadece syntax farklı.

// temel arrow function
const add = (a: number, b: number): number => a + b;

// dönüş tipi genelde çıkarılır (inference), yazmak zorunda değilsin
const greet = (name: string) => `Merhaba ${name}`;

// gövdesi { } olduğunda return tipini TS otomatik anlar
const isEven = (n: number) => {
  return n % 2 === 0; // boolean olarak çıkarılır
};

// parametresiz
const getTimestamp = (): number => Date.now();
fark — arrow function'lar kendi this'ini bağlamaz, çevresindeki scope'un this'ini kullanır. Class component metotlarında (artık nadir) bu yüzden tercih edilirdi.
TYPE / 07

Fonksiyonu değer olarak tiplemek

Bir fonksiyonu parametre ya da prop olarak geçerken tipini nasıl yazarsın.

// fonksiyon tipi: (parametreler) => dönüş tipi
type AddFn = (a: number, b: number) => number;

const add: AddFn = (a, b) => a + b; // parametrelerin tipini tekrar yazmana gerek yok

// callback parametresi olarak fonksiyon almak
function repeat(times: number, callback: (index: number) => void) {
  for (let i = 0; i < times; i++) callback(i);
}

repeat(3, (i) => console.log(i)); // i otomatik number olarak çıkarılır

// void dönüş tipi: "dönüş değeri önemli değil" demek, undefined ile aynı değil
RN'de nerede görürsün RN — onPress: () => void, onChangeText: (text: string) => void gibi prop tanımlarının tamamı bu mantıkla yazılır.
TYPE / 08

Async / await ve Promise

Asenkron fonksiyonların dönüş tipi her zaman bir Promise'e sarılır.

// dönüş tipi otomatik Promise olur, T'yi belirtmen yeterli
async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/users/${id}`);
  return res.json(); // TS burada User olduğuna güvenir, kontrol etmez
}

// çağırırken await edersen Promise açılır, T kalır
const user = await fetchUser(1); // user: User

// dönüş değeri olmayan async fonksiyon
async function logIn(): Promise<void> {
  await authenticate();
}
dikkat — res.json() tipi aslında any döner, Promise<User> yazman TS'e güvenmesini söyler ama runtime'da veri gerçekten o şekilde gelmeyebilir. API response'unu doğrulamak istersen zod gibi bir kütüphane işine yarar.
TYPE / 09

Fonksiyon overload

Aynı fonksiyonun farklı parametre kombinasyonlarıyla farklı davranmasını tiplemek.

// overload imzaları (implementasyonsuz, sadece tip bildirimi)
function makeId(value: number): number;
function makeId(value: string): string;

// gerçek implementasyon, parametre tipi union olmalı
function makeId(value: number | string) {
  return value;
}

const a = makeId(5);      // tip: number
const b = makeId("x");    // tip: string
ne zaman gerekir — günlük RN kodunda nadiren ihtiyaç duyarsın, ama bir kütüphanenin tip tanımlarını okurken (örneğin react-navigation) sık karşına çıkar, o yüzden tanıması önemli.
TYPE / 10

Union & Intersection

Union "ya bu ya bu", intersection "hepsi birden".

type ID = string | number; // union

type Named = { name: string };
type Aged = { age: number };
type Person = Named & Aged; // intersection

const p: Person = { name: "Yigit", age: 21 };
TYPE / 11

Type narrowing

Union tipi runtime kontrolüyle daraltmak.

function printId(id: string | number) {
  if (typeof id === 'string') {
    console.log(id.toUpperCase()); // artık string
  } else {
    console.log(id.toFixed(2)); // artık number
  }
}

// obje tiplerinde: 'in' operatörü
if ('email' in user) { /* ... */ }

// class instance'larda: instanceof
if (error instanceof Error) { /* ... */ }
TYPE / 12

Optional chaining & nullish

null/undefined kontrolünü kısaltan operatörler.

// optional chaining: zincirde biri null/undefined ise durur
const city = user?.address?.city;

// nullish coalescing: sadece null/undefined ise fallback verir
const displayName = user.name ?? 'Anonim';

// dikkat: || farklıdır, 0 ve "" gibi falsy değerleri de değiştirir
const count = user.score || 10; // score 0 ise 10 olur, muhtemelen istemezsin
const countFixed = user.score ?? 10; // score 0 ise 0 kalır
sık hata — || ile ?? karıştırılır. Sayısal değerlerde (score, count) neredeyse hep ?? istersin.
03 — GENERİC'LER & YARDIMCI TİPLERgenerics & utility types
TYPE / 13

Generics

Tipi çağrı anında parametre gibi geçmek.

function wrapInArray<T>(item: T): T[] {
  return [item];
}

const nums = wrapInArray<number>(5); // number[]

// birden fazla generic parametresi
function merge<A, B>(a: A, b: B): A & B {
  return { ...a, ...b };
}

// generic'e kısıt (constraint) koymak
function getLength<T extends { length: number }>(item: T) {
  return item.length;
}
RN'de nerede görürsün — useState<string | null>(null), useRef<TextInput>(null) ve API response tiplerinde her yerde.
TYPE / 14

Utility types

TypeScript'in hazır sağladığı tip dönüştürücüler.

interface User { id: number; name: string; email: string; }

Partial<User>      // tüm alanlar opsiyonel
Required<User>     // tüm alanlar zorunlu
Readonly<User>     // tüm alanlar salt okunur
Pick<User, 'id' | 'name'>   // sadece seçilenler
Omit<User, 'email'>        // seçilenler hariç
Record<string, User>       // key-value map tipi
pratik kullanım — bir form component'inde tüm alanlar zorunlu olan User tipini, düzenleme ekranında Partial<User> yaparak kısmi güncellemeye izin verirsin.
TYPE / 15

Type assertion

Derleyiciye "buna güven" demenin (riskli) yolu.

const input = document.getElementById('x') as HTMLInputElement;

// non-null assertion: kesin null olmadığını iddia etmek
const el = document.getElementById('x')!;

// açı parantez yazımı da var ama .tsx dosyalarında JSX ile
// karıştığı için 'as' yazımı tercih edilir
dikkat — assertion, runtime kontrolü yapmaz, sadece derleyiciyi susturur. Yanlışsa çalışma zamanında patlar. Mümkünse narrowing tercih et.
TYPE / 16

Modül import / export

Tip ve değer export'larını ayırmak.

// named export
export interface Props { title: string; }
export function Button(props: Props) {}

// sadece tip import etmek istersen (derleme sonrası kod üretmez)
import type { Props } from './Button';

// default export
export default Button;
04 — REACT NATIVE'DE TYPESCRIPTapplied patterns
RN / 17

Component props RN

Fonksiyon component'inin prop şeklini tanımlamak.

interface ButtonProps {
  label: string;
  onPress: () => void;
  disabled?: boolean; // opsiyonel prop
}

function CustomButton({ label, onPress, disabled }: ButtonProps) {
  return (
    <TouchableOpacity onPress={onPress} disabled={disabled}>
      <Text>{label}</Text>
    </TouchableOpacity>
  );
}
RN / 18

useState ile generic RN

State'in tipini TypeScript çoğu zaman kendi çıkarır, ama belirsiz olduğunda generic ver.

// tip otomatik çıkarılır: boolean
const [loading, setLoading] = useState(false);

// başlangıç değeri null olduğunda tip belirsizleşir, generic ver
const [user, setUser] = useState<User | null>(null);

const [items, setItems] = useState<string[]>([]);
RN / 19

Event handler tipleri RN

RN'de web'deki gibi ChangeEvent yok, kendi event tipleri var.

import { NativeSyntheticEvent, TextInputChangeEventData } from 'react-native';

function handleChange(
  e: NativeSyntheticEvent<TextInputChangeEventData>
) {
  console.log(e.nativeEvent.text);
}

// çoğu zaman daha basiti yeterli:
function handleText(text: string) {}
<TextInput onChangeText={handleText} />
RN / 20

children ve navigation tipleri RN

Component'e children geçirmek ve navigation prop'larını tiplemek.

import { PropsWithChildren } from 'react';

interface CardProps {
  title: string;
}

function Card({ title, children }: PropsWithChildren<CardProps>) {
  return <View><Text>{title}</Text>{children}</View>;
}

// react-navigation ile screen prop tiplemek
type RootStackParamList = {
  Home: undefined;
  Profile: { userId: string };
};
not — Profile: { userId: string } demek "Profile ekranına geçerken userId parametresi zorunlu" demek. undefined ise parametre almıyor demek.
